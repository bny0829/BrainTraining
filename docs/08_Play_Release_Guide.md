## 四、Play Console 表單答案

**資料安全（Data safety）**——全部照實填「不收集」：
- 是否收集或分享使用者資料？ → **否**
- 資料是否加密傳輸？ → 不適用（無網路功能）
- 使用者能否要求刪除資料？ → 不適用

**廣告 ID 聲明**：目前版本沒有整合任何廣告/追蹤 SDK，選 **「否，不使用廣告 ID」**。未來接 AdMob 後這裡要改回「是」，並同步更新隱私權政策與資料安全表。

**內容分級問卷**：益智遊戲、無暴力/賭博/色情/使用者互動 → 會拿到全年齡（3+）。

**廣告**：本 App 不含廣告 → 否。

**目標對象**：13 歲以上（選含兒童會多很多審查要求，先避開）。

以上這些都是 App 層級的設定，**封測時已經填過，正式版不用重填**（除非內容有變動）。

## 五、匯出 AAB（Play 只收 AAB，不收 APK）

1. Godot 選單：**專案 → 安裝 Android 建置樣板…**（一次性；已裝過的話會跳過）
2. 專案 → 匯出 → Android 預設組：
   - `Gradle 構建 / 使用 Gradle 構建` 打勾
   - `匯出格式` 選 **Export AAB**
   - Export Path 改成 `./BrainClub.aab`
3. 確認已重啟過 Godot（讀取金鑰環境變數），**不要**勾「以除錯模式匯出」
4. 按「匯出專案」

版號規則：每次上傳 Play 的 `version/code` 必須**比前一次上傳大**（目前 13 / v0.9.0）。

## 六、推出正式版（封測已通過，現在的重點）

**重要觀念**：Google 的「封閉測試 12 人×14 天」是**帳號／App 層級的一次性資格門檻**，一旦達成，就能把**任何版本**（不必是封測時那個 build）直接送去正式版軌道，不需要為每個新版重跑 14 天測試。

**建議直接推出目前的 v0.9，不要用封測時測過的舊版**：v0.9 修掉了封測期間發現的真實 bug（新接龍卡死、英文介面版面溢出），首批玩家的評價非常重要，值得多花一次上傳的時間換取更好的第一印象。

步驟：
1. 依第五節匯出 v0.9.0 的 AAB
2. Play Console → 左側「**正式版**」（Production）→ 建立新版本 → 上傳這個 AAB
3. 填寫「本次更新內容」（第三節已準備好文案）
4. 檢查商店資訊分頁的截圖/文案是否需要更新為 v0.9 版本（本次已重新產生）
5. 送出審查——**首次正式版審查通常比測試軌道久**，可能數小時到數天
6. 通過後 App 會在 Play 商店公開上架

### 讓國外使用者也能安裝（地區設定）
